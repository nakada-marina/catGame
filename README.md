# ぐりおのねこカフェ

店長ねこ「ぐりお」といっしょに、小さなねこカフェを人気のお店に育てるドット絵の経営シミュレーションゲームです。
`index.html` と同じフォルダの画像・JavaScriptを配置して、ブラウザで遊べます。

## 動くカフェのタイトル画面

タイトルは画面いっぱいの朝のカフェです。猫2匹の位置は固定し、ぐりおのコーヒーの湯気や、ぽんたの睡眠・毛づくろいをその場で表示します。吹き出しはぐりおの位置に揃え、猫をタップすると挨拶します。「はじめから」と、セーブがある場合の「つづきから」から営業へ進めます。右上の「動き」で停止・再開でき、端末の視差効果を減らす設定では最初から静止表示します。

`title-cafe.png` と `title-cafe-mobile.png` は画像生成ツールで制作した文字・キャラクターなしの背景です。縦画面では窓・ソファ・カウンターが見える専用の構図へ切り替え、必要な背景だけを読み込みます。`title-scene.js` が既存のぐりお・ぽんたの素材を重ね、`title-screen.css` が縦画面・横画面のメニューを配置します。PCの横画面ではメニューを右側に置き、セーブの有無や画面サイズに応じて猫とボタンの間隔を確保します。タイトルの動きはセーブや営業時間を変更せず、営業開始時に停止します。背景を読み込めない場合も開始ボタンは使えます。

Playwrightの `node tests/title-check.cjs` で縦横の背景切り替え、セーブありでの猫とボタンの重なり、モーションの描画と停止、新規開始・セーブ再開、動きを減らす設定、背景読み込み失敗を検証します。`CHROMIUM_PATH` と `BASE_URL` も指定できます。

## はじめての接客

新しく始めると、最初のお客さん一人へのコーヒーの接客を、注文→調理→配膳の順に画面上で案内します。案内中は営業時間と待ち時間を止め、猫の自動接客を待たせます。調理は緑の範囲で待機し、早すぎるタップはやり直せます。完成したコーヒーも冷めません。案内を完了またはスキップすると通常営業に戻ります。完了は既存のセーブキー内のフラグへ保存し、更新前のセーブには案内を追加しません。

`node tests/first-customer-check.cjs` で接客の一連の流れ、待ち時間・時計の停止、早いタップの再試行、各段階のスキップ、完了後の通常営業・保存再開を確認できます。Playwrightの `tests/browser-check.cjs` には実際の店内・キッチンのタップで進む検証もあります。

## あそびかた

- **ふきだしをタップ**：注文をうける。注文は画面下のキッチンに伝票として届きます。待たせすぎると怒って帰ってしまいます。しばらくだれも注文をききに行かないと、手の空いたねこがメモを持って注文をとりに行きます（材料があるときだけ。「配膳がはやい」ねこは注文とりもはやい）
- **キッチン**：設備をタップすると調理スタート
  - コーヒーマシン（コーヒー・ミルクティー・パフェ）：カップのみどりの線までたまったらタップ
  - フライパン（パンケーキ・オムライス）：きつね色でキラキラしたらタップ
  - オーブン（クッキー・ケーキ）：ベルが光ったらタップ
  - ちょうどいいときにタップすると「パーフェクト！」で満足度とチップがアップ。早すぎると失敗
  - できた料理は「できあがり」台にならび、ねこたちが自動で席まで運ぶ。急ぐときは台の料理をタップですぐ届く。放っておくと冷める
  - ショップの「キッチン」で2台目の設備を買える
- **レジ・お会計**：レジは入口の右側。食後のお客さんがレジへ移動します。店内のレジをタップすると支払いを受け取り、料理代とチップが売上に加わります。現金はすぐ使えるお金に、カードは入金待ちの売掛金になります。少し待つと自動会計、アルバイトさんがいると早めに会計します。レジ前は3人までで、満員のときは席で待ちます。立った席のお皿は片付けられます。
- **テーブルのお皿**：ねこたちが回収します。急ぐときはタップで片付け。回収された食器は洗い待ちになり、洗うまでは再使用できません。
- **洗い物**：洗い場をタップ、または「洗い物」から「洗う」で、コップ・皿・フォークを合計3個ずつ洗います。営業中は通常速度で3秒（画面を閉じて進行）、閉店後はその場で洗えます。人のアルバイトは空き時間に洗います。清潔・使用中・洗い待ちの数を確認でき、ショップの「食器」で2個ずつ追加できます。
- **セット注文**：通常営業では約30%のお客さんが飲み物＋スイーツを注文します。コーヒー＋ケーキ、ミルクティー＋クッキーなど、解放したメニューから選びます。各品を別々に調理・配膳し、全部揃ってから食事。レジで合計金額とチップを一度だけ受け取ります。
- **ねこをタップ**：なでる（ごきげんUP）
- **床のねこの毛をタップ**：おそうじ。毛が多いとお客さんの満足度が下がります
- **ごはん**：ねこのごはんを補充。おなかがすいたねこは元気がなくなります
- **仕入れ**：料理の材料を買う。材料がないと料理を出せません（ふきだしに✕）
  - 通算1・4・7・10日目…の3日に1回。営業中と閉店後は同じ価格。買掛で受け取るので購入時の現金は減らず、10日ごとの月末の閉店時にまとめて支払います。仕入れ日以外は次の仕入れ日を表示します。
  - 材料の値段は毎日かわります（やすい／たかい）
  - 牛乳・たまご・いちご・生クリームは日もちが短く、使いきれないと捨てることに
  - 冷蔵庫とたなに入る量には上限あり。ショップで大きくできます
  - カウンターの上の「材料だな」で在庫が目で見える。空っぽは赤、あすで期限切れは黄色の「!」。たなをタップで仕入れ画面
- **ショップ**：カウンター席（3席まで）、テーブル、キャットタワー、クッション、観葉植物などの家具や新メニュー、新しいねこ、アルバイトさん
- **シフト**：ぽんたと迎えた猫（ミケ・クロ・シロ・チャチャ）が好きな勤務時間や休みを希望します。1か月10日、今月と来月の希望を見ながらオーナーが出勤・休みと10:00〜19:00の勤務時間を1時間単位で調整できます。「保存」で変更、「希望に戻す」で元の希望へ。予定は自動保存され、開き直しても希望は変わりません。リザルトの「あすのシフト」から準備でき、閉じるとリザルトへ戻ります。
- **ニャイミー**：スキマ時間にはたらきたい野良ねこを、数時間だけ雇えるアプリ。日替わりで3匹が応募。配膳がはやい・片付けじょうず・招きねこ（お客さんがふえる）・いやし系（満足度アップ）の得意わざあり。報酬は来てもらうときに払う
- **ニャックス**：店長ぐりおが毎日の閉店後に、その日のお店のことを勝手につぶやくSNS（お客さんの数、パーフェクトな料理、新しいなかま、ぽんたの昼寝回数、ほめられたメニューなど＋閉店後のお店の写真）。ポストは結果画面でも見られる。いいねはつぎの日の営業中に伸び、一定をこえるとバズってお客さんがどっと来る。フォロワーが多いほど、ふだんのお客さんも少しふえる。満足したお客さんや怒ったお客さんのポストもタイムラインに流れる
- **はやさ**：×1 / ×2 / ×3

1日は 10:00〜19:00。閉店すると売上とお客さんの声が見られます。
ねこがお客さんのそばに行くと満足度が上がり、チップがもらえることも。

店長のぐりおは毎日勤務。弟の **ぽんた** は2日目から無料のおてつだいに来ます。希望は2・4・6日目…の隔日で、「シフト」から変更できます。ぽんたはできた料理を席まで運んでくれますが、よく寝たり毛づくろいでサボったりします（タップで起こせます）。

店長のぐりおが、はじめての説明や「SNSで話題に！」「常連さんが来た！」などのイベントで話しかけてきます。

目標は **ひょうばん ★5** と **もちきん ¥100,000**。進行はブラウザに自動保存されます。HUDの金額は使えるお金、売掛表示はまだ入金されていないカード売上です。「帳簿」で入金・支払い予定を確認できます。

## ニャックスのお客さんの料理写真

満足したお客さんがニャックスへ投稿すると、食べた料理のドット絵写真が添えられます。コーヒー・ねこクッキー・ミルクティー・いちごケーキ・パンケーキ・ねこオムライス・にくきゅうパフェの7品に対応し、コーヒーにはクッキーと一緒に写した構図もあります。セット注文でも食べた料理の写真を添えます。待ちきれずに帰ったお客さんの投稿は文章のみです。投稿確率・売上・評判の計算は従来どおりです。

`nyax-food-atlas.png` は画像生成ツールで制作した料理写真8枚のドット絵素材です。`nyax-art.js` が各写真を縦横比を保って表示します。保存には料理IDと構図だけを追加し、40件の投稿に画像データを重複保存しません。以前の文章のみの投稿やぐりおの店内写真も表示できます。素材の読み込みに失敗した場合は既存の料理ドット絵を使います。

Playwrightで `node tests/nyax-check.cjs` を実行すると、実際の会計から7品の投稿、二重投稿防止、保存再開・40件保持、旧投稿、画面幅320/393/1280pxでの表示と素材の読み込み失敗を検証します。既存のブラウザテストと同様に `CHROMIUM_PATH` と `BASE_URL` を指定できます。

## キャラクター素材と表示検証

ぐりおとぽんたの全身素材は `cat-motions-grio.png` と `cat-motions-ponta.png`（各1024×1536、各24コマ）に揃えています。前・後ろ・右向きの歩行を各4コマ、待機、配膳、コーヒー／ケーキ、掃除、座る、睡眠、箱での睡眠、驚く、喜ぶ、お辞儀、ジャンプ、毛づくろいを同じキャラクター見本から描き直しました。ぐりおは短毛のキジ白、ぽんたは長毛の茶色キジトラ。ぽんたに白い毛はなく、口元・あご・胸・手足まで茶色で揃えています。黒いエプロン、金色の縁、オレンジの猫模様を共通にしています。

店内は最大640pxの横幅を維持し、高さを従来の半分（縦横比300:448）にしました。家具・猫・客は基準位置だけを上下に移動させ、全身を縦につぶしません。壁・床は短い画面の座標で描き、装飾は縦横同じ倍率で配置します。操作ドックと会話位置を維持します。セーブキー `grio-cafe-v1` を維持し、旧セーブを読み込めます。

`touch-controls.js` は連続タップの標準ズームを抑止し、ボタンは1タップ1クリックで処理します。縦ドラッグと複数指ジェスチャーは維持します。Canvasは表示領域とDPRから内部解像度を決めます。猫の元画像は一度だけ補間して描き、背景のドット描画は設定を保持します。

## 猫の表示サイズとモーション

ぐりおの全身は0.55倍（70×79の表示フレーム）、ぽんたは0.52倍（67×75）で表示します。全身素材は全ポーズ128×144です。`CatArtwork.displaySize` に倍率を集約し、待機・歩行・仕事・休憩で表示倍率を変えません。ニャイミーの野良猫も128×144の素材を0.52倍（67×75）で表示します。他4種類の猫は引き続き0.78倍です。

斜めを含む画面奥への移動は後ろ姿、手前へは前向き、真横は左右向きです。他4種類の猫は `cat-facing-extra.png`、人の後ろ姿は `rear-walk-atlas.png` を使います。保存形式は維持しています。

## ニャイミーの野良猫の統一素材

サビ・ハチ・グレ・ミルク・ボス・コテツを、ぐりお・ぽんたと同じ温かいドット絵、頭身、輪郭、足元の基準で描き直しました。黄色いバンダナを共通の目印にし、各猫の毛色・白い部分・毛の長さを全ポーズで統一しています。一覧・勤務中・「ねこたち」は同じ素材を使います。

## レジでの会計

食事終了時に満足度・チップ・常連ボーナスを一度だけ計算し、会計待ちの間は変えません。客は席で待つ→レジへ歩く→先頭で支払い→帰る、の順に進みます。先頭の客に対する手動・自動会計は同じ `pay()` を使い、売上・チップ・接客数・レビュー・SNSを一度だけ更新し、金額と進行を保存します。レジ前は最大3人、自動会計は先頭到着後240フレーム、空いているアルバイトは90フレーム。36フレームの支払い演出後に出口へ向かい、会計待ちと退店が終わってから閉店レポートを出します。時計・速度・一時停止は通常の営業と共通です。

レジは店内の木製カウンターとセージ色の機械で表示し、受け取り音・金額・硬貨・レシートを描画します。店内のCanvasに描かれたレジをタップして操作でき、注文のタップ領域が重なる場所では注文を優先します。画面下の会計欄と会計ボタンは廃止し、会計待ちが増えてもキッチンの表示領域が変わらないようにしています。会計待ちでもシンクをタップして皿洗いができます。客が立つと座席を切り離してお皿を残し、支払い時に再使用された座席を変更しません。保存キー・メニュー価格・チップの計算式は維持しています。

`node tests/register-check.cjs` は実際の会計・客更新・閉店・保存・Canvas操作のコードを使って、会計待ちの間の洗浄、手動と自動、二重会計の防止、満足度の固定、チップと常連ボーナス、座席再使用、最大15人の会計と閉店、保存再開、表示座標とタップの優先順を検証します。`tests/browser-check.cjs` には店内レジの実タップ・表示・保存再開の検証もあります。


## 10日で1か月の簡略経理

`finance.js` がゲーム内の経理を担当します。通算1〜10日が1月、11〜20日が2月です。実際の暦・税制・社会保険制度を再現する計算ではありません。

- お客さんの40%がカード払い。現金売上はその場で使えるお金に加わります。カードは売掛金として保持し、月末締め・翌月2日入金。手数料は会計ごとに3%を円単位へ四捨五入し、カード売上から相殺します。1月のカード売上は通算12日目に入金されます。
- 税金は月の黒字の10%で月末に確定します。赤字の月は税金0円。店長の健康保険400円・年金600円／月、スタッフ社会保険は支払った給与の10%をお店が負担します。保険料は日ごとに経費へ計上し、税金と一緒に翌月3日に支払います。1月分は通算13日目に支払います。
- 家賃1,000円／日、電気100円・水道30円・通信20円／日。アルバイト給与は従来どおり2,000円／日。仕入れ、食器購入費、猫のごはん、ニャイミー、採用、猫を迎える費用、メニュー開発費を分けて記録します。
- 仕入れは3日ごとに、購入日に経費と仕入れ買掛へ計上し、月末（通算10・20・30日）の閉店時に支払います。支払い時に経費を重複させません。設備・家具は設備投資として資金の増減に表示し、営業利益からは引きません（減価償却なし）。食器は購入日に食器購入費へ計上します。閉店後の購入は次の営業日の帳簿へ入ります。
- リザルトは売上と営業利益、経費の内訳、実際のお金の増減、カード売掛・入金予定、月ごとの集計を分けて表示します。仕入れ・ごはん・採用・開発・設備は名前と金額の明細も開けます。利益に計上済みのカード手数料、保険料、税金を、入金・支払いのときに再度利益から引きません。
- 「帳簿」は営業中もリザルトからも開けます。リザルトから閉じるとリザルトへ戻り、営業日を進めません。カード売上は入金まで使えるお金に加わりません。仕入れは買掛で現金残高に関係なく受け取れますが、家具・食器・採用などは使えるお金が必要です。月末や定期支払いで使えるお金がマイナスになることはあります。
- 売掛・買掛、支払い済みフラグ、進行中の日の経理を既存のセーブへ保存します。入金・月次支払いを再読み込みで重複させません。旧セーブは更新後から集計し、過去の税金や保険料を遡って請求しません。支払い済みの旧仕入れ費は二重に引かず、明細だけ一度移します。

`node tests/finance-check.cjs` で10日の月境界、カード売掛・手数料・入金、税金・保険・給与、資金の増減式、月末と再読み込みの重複防止、旧セーブと閉店後の仕入れ、リザルトの明細を検証します。`tests/register-check.cjs` は実際の現金・カード会計も検証します。Playwrightの `tests/browser-check.cjs` には会計表示、帳簿とリザルトの往復、翌月2日の入金・3日の支払い・保存再開の検証があります。


## 猫の希望シフトと無料のおてつだい

`cat-shifts.js` はぽんたと迎えた4種類の猫の希望・オーナーの調整をセーブに保持します。ぽんたは評判や所持金に関係なく通算2日目から無料で来て、初期希望は偶数日に10:00〜19:00。2日目から奇数日の出勤や休みにも変更できます。以前ぽんたを雇ったセーブも新しい無料・隔日の予定へ移行します。ぐりお、ニャイミー、人のアルバイトはシフト表の調整対象外です。猫の追加給与はなく、人の採用費・日給とニャイミーの契約時間・報酬は従来どおりです。

ほかの猫は朝・午後などそれぞれの傾向に沿って勤務時間や休みを希望します。希望は今月と来月について一度生成し、月が変わっても予約済みの調整を引き継ぎます。開始時刻に出勤し、終了・休みへの変更で注文・配膳・片付けの担当を解除して出口へ向かいます。当日の延長でも同じ猫を重複させません。休みの猫は所有データとごきげん・おなかを保持し、再購入の対象になりません。営業中に迎えた猫はその日の残り時間をまず手伝います。

`node tests/shifts-check.cjs` は無料の2日目参加と隔日、旧セーブ、月の境界と希望の固定、オーナー調整と実際の画面ハンドラー、出退勤と仕事の担当解除、休みの所有・状態の保持と再購入防止、保存再開、リザルトへの復帰、ニャイミーと人の給与を検証します。`tests/browser-check.cjs` には実画面でのシフト操作・表示・保存再開の検証もあります。

## 入口のレジ、セットと食器の在庫

レジを入口右側へ移し、3人の会計列は入口の横へ並ぶようにしました。テーブルと椅子の6組、カウンター、床の小物を配置し直しています。洗い場は画面下のキッチンにあります。カウンターの前側で客の下半身を隠し、カウンター席の料理を表示する専用レイヤーを追加しました。セットの2品は各客の卓上の範囲へ配置します。

3日ごとの仕入れに合わせ、いちごと生クリームの日もちを3営業日へ揃えました。余った分は3日目の閉店時に廃棄し、次の仕入れ日に補充します。

`cafe-service.js` は仕入れ日、セットの材料・価格・必要食器、清潔／使用中／洗い待ち／洗っている食器を管理します。初期は各6個。注文時に必要数を確保できない場合は材料を消費せず、注文を受けられません。食器は食後にテーブルへ残り、回収後に洗い待ちへ移ります。通常営業の途中で再開すると、以前の客が使用していた食器を洗い待ちへ戻し、数を増減させません。未完了の初回案内で確保したコップは再開時に清潔へ戻します。洗浄途中の食器・進行と購入した総数も保存します。

セットは一つの注文を複数の調理伝票へ分け、各品の配膳後も残りを待ちます。全品が揃ったら食事を開始し、冷めた品があればセット全体も冷めた評価、全品パーフェクトならパーフェクトになります。途中で帰った場合は残りの伝票をまとめて取り消し、確保した食器を洗い待ちへ戻します。
